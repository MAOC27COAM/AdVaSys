## 9.3.1 Modelo del sistema / mapa de procesos

El sistema academico ADUNI Vallejo es una aplicacion web cliente-servidor (React + Node.js/Express + PostgreSQL/Prisma) que centraliza la operacion academica y administrativa por **ciclo lectivo**. Los procesos principales son:

```mermaid
flowchart TB
  subgraph transversal [Procesos transversales]
    Auth[Autenticacion JWT]
    Ciclo[Seleccion de ciclo activo]
  end

  subgraph staff [Procesos administrativos]
    Matricula[Matricula y carnets]
    Pagos[Gestion de pagos]
    Asistencia[Asistencia por QR]
    Simulacros[Simulacros y resultados]
    Usuarios[Consulta y exportacion]
    Materiales[Material de cursos]
  end

  subgraph student [Procesos del estudiante]
    MatConsulta[Consulta de materiales]
    MisResultados[Mis resultados]
    MisAsistencias[Mis asistencias]
    Perfil[Perfil y QR]
  end

  Auth --> Ciclo
  Ciclo --> Matricula
  Ciclo --> Pagos
  Ciclo --> Asistencia
  Ciclo --> Simulacros
  Ciclo --> Usuarios
  Matricula --> Pagos
  Simulacros --> MisResultados
  Asistencia --> MisAsistencias
  Materiales --> MatConsulta
```

**Nota sobre roles internos:** el sistema incluye el rol `kami` (superusuario operativo). Para la documentacion de tesis se modelan solo los tres actores principales: **Administrador**, **Matriculador** y **Estudiante**.

---

## 9.3.2 Tabla 6. Actores del sistema

| Actor | Descripcion |
|-------|-------------|
| **Administrador** | Actor interno con supervision total de la plataforma. Gestiona matricula, ciclos, pagos, usuarios, asistencia administrativa, simulacros, material de cursos, carnets e importacion masiva por Excel. Puede eliminar eventos e instancias de simulacro y crear usuarios con rol administrador. |
| **Matriculador** | Actor interno de operacion academica diaria. Comparte con el administrador el acceso a matricula, ciclos, pagos, usuarios, asistencia, simulacros, materiales, carnets e importacion Excel. No puede eliminar eventos/instancias de simulacro en la interfaz ni crear usuarios administradores. |
| **Estudiante** | Actor externo matriculado. Consulta material de cursos permitido por modalidad, sus resultados de simulacros, su perfil personal con codigo QR de asistencia y su historial personal de asistencia. No accede a modulos administrativos. |

*Fuente: elaboracion propia (sistema ADUNI Vallejo, 2026).*

## Anexo A. Diagramas de secuencia (flujos criticos)

### A.1 Simulacro RAW — analizar y procesar

```mermaid
sequenceDiagram
  participant Admin as Administrador
  participant UI as Frontend
  participant API as Backend
  participant BD as PostgreSQL

  Admin->>UI: Crear evento y definir clave respuestas
  UI->>API: POST /simulations/events
  API->>BD: INSERT SimulationEvent cycleId

  Admin->>UI: Analizar archivo Excel RAW
  UI->>UI: Parsear DNI columna A
  UI->>API: POST /simulations/validate-codes
  API->>BD: Consultar User y CycleEnrollment
  API-->>UI: Tabla FOUND NOT_FOUND NOT_ENROLLED INACTIVE
  Note over UI,BD: No se crea instancia en BD

  Admin->>UI: Procesar y guardar resultados
  UI->>API: POST /events/:id/instances/process-raw
  API->>BD: CREATE SimulationInstance
  API->>API: Calificar vs answerKey
  API->>BD: INSERT SimulationResult + rankings
  API-->>UI: instanceId
  UI->>UI: Navegar a resultados
```

### A.2 Matricula con pago inicial

```mermaid
sequenceDiagram
  participant Mat as Matriculador
  participant UI as Frontend
  participant API as Backend
  participant BD as PostgreSQL

  Mat->>UI: Completar formulario matricula
  UI->>API: POST /students/enrollment
  API->>BD: Validar DNI y ciclo operable
  API->>BD: CREATE User + StudentProfile
  API->>BD: CREATE CycleEnrollment
  API->>BD: CREATE PaymentAgreement + Installments
  API->>BD: Registrar pago inicial si aplica
  API-->>UI: Estudiante matriculado
  UI->>UI: Actualizar tabla matriculados
```

### A.3 Sesion de asistencia

```mermaid
sequenceDiagram
  participant Mat as Matriculador
  participant UI as Frontend
  participant API as Backend
  participant BD as PostgreSQL

  Mat->>UI: Iniciar sesion asistencia
  UI->>API: POST /attendance/session/start
  API->>BD: CREATE AttendanceSession cycleId
  API-->>UI: sessionId activo

  Mat->>UI: Escanear QR estudiante
  UI->>API: POST /attendance/record
  API->>BD: INSERT AttendanceRecord PRESENT
  API-->>UI: Confirmacion + sonido

  Mat->>UI: Activar modo tardanza
  Mat->>UI: Escanear estudiante tardio
  UI->>API: POST /attendance/record
  API->>BD: UPDATE estado LATE

  Mat->>UI: Finalizar sesion
  UI->>API: PATCH /attendance/session/end/:id
  API->>BD: Marcar no registrados ABSENT
  API-->>UI: Sesion cerrada
```
