📁 Backend

1. `backend/prisma/schema.prisma`
       **\* Contexto: Es el "plano" de tu base de datos. Aquí se definieron los nuevos modelos**

         **SimulationEvent (el evento de simulacro), AcademicModality (los grupos de estudiantes como**

         **PRE-U, COAR) y la tabla que los une. Es la base de toda la nueva lógica.**




2. `backend/src/routes/simulations.js`
       **\* Contexto: Define las URLs de la API para el módulo. Se añadieron las nuevas rutas para manejar**

         **los eventos y las validaciones, como POST /events (para crear un evento), GET /events (para**

         **listarlos), y POST /validate-codes (para la validación de códigos de estudiante).**




3. `backend/controllers/simulationController.js`
       **\* Contexto: Es el "controlador de tráfico" de la API. Recibe las peticiones web, se asegura de**

         **que todo esté en orden (como los datos enviados) y llama al servicio correspondiente para**

         **hacer el trabajo. Se añadieron y modificaron funciones para que coincidan con las nuevas rutas**

         **(ej. createSimulationEvent, getSimulationEvents, validateStudentCodes).**




4. `backend/services/simulationService.js`
       **\* Contexto: Aquí reside la "lógica de negocio" del backend. Este archivo contiene las funciones**

         **que realmente interactúan con la base de datos (usando Prisma) para crear, leer o actualizar**

         **datos. Fue completamente refactorizado para usar los nuevos modelos SimulationEvent y**

         **AcademicModality.**




---

🎨 Frontend

1. `frontend/src/components/Modulo\_Simulacro/SimulationModule.js`
       **\* Contexto: Es el componente principal y contenedor de todo el módulo. Lo rediseñé para tener el**

         **layout de dos paneles que describiste: un panel izquierdo para la navegación (listar**

         **modalidades y eventos) y un panel derecho donde se renderizan los otros componentes.**




2. `frontend/src/components/Modulo\_Simulacro/SimulationEventManager.js`
       **\* Contexto: (Anteriormente SimulationModalityManager.js). Esta es la interfaz para "Gestionar**

         **Eventos". Contiene el formulario que permite crear un nuevo evento de simulacro (dándole un**

         **nombre, número de preguntas y asociándolo a modalidades académicas).**




3. `frontend/src/components/Modulo\_Simulacro/SimulationInstanceUpload.js`
       **\* Contexto: El corazón del nuevo flujo interactivo. Este componente se activa cuando seleccionas**

         **un evento. Se encarga de:**

           **\* Leer el archivo Excel que seleccionas directamente en el navegador.**

           **\* Extraer los códigos de la primera columna.**

           **\* Enviar esos códigos al backend para validarlos y mostrarte cuáles se encontraron y cuáles**

             **no.**

           **\* Presentar el botón "Llenar respuestas".**




4. `frontend/src/components/Modulo\_Simulacro/AnswerKeyModal.js`
       **\* Contexto: Un nuevo componente que muestra una ventana modal para que puedas introducir la**

         **clave de respuestas (alternativa correcta) para cada una de las preguntas del evento de**

         **simulacro.**




5. `frontend/src/services/simulationService.js`
       **\* Contexto: El "mensajero" del frontend. Contiene todas las funciones (fetch) que el frontend**

         **usa para hablar con la API del backend. Fue completamente actualizado para llamar a las nuevas**

         **rutas de la API que creamos.**




6. Archivos de Estilos (`.css`)
       **\* `SimulationModule.module.css`: Contiene los estilos para el layout principal de dos paneles.**

       **\* `SimulationInstanceUpload.module.css`: Contiene los estilos para el panel derecho, incluyendo**

         **el área de carga de archivos y la tabla de validación, para que se parezca a los bocetos.**




Con este resumen, tienes el mapa completo de las piezas involucradas y su función en el sistema.
