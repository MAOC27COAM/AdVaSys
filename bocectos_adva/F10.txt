Para esta beta, te recomiendo esto:

1. En la PC Academia correr:

   - `Reverse proxy` local

   - servirlo como sitio estático

   - Local: `http://192.168.18.149`
   - Remoto: `https://gestion.academia.com`
   - `/api` al backend
   - `/uploads` al backend o al almacenamiento estático
   - `/` al frontend compilado

Eso reduce muchísimo problemas de CORS, puertos, `localhost`, y Cloudflare.

**Lista detallada para realizarlo**

**Fase 1. Preparar el sistema para producción**
- Corregir [frontend/.env.production](C:\BIBLIOTECA\INTRANET%20VALLEJO\frontend\.env.production) para que no use `localhost`.
- Eliminar o consolidar componentes duplicados del frontend donde todavía queden rutas antiguas.
- Revisar y centralizar todas las llamadas API para que usen una sola configuración.
- Definir `CORS_ORIGINS` reales para local y remoto en backend.
- Corregir el Dockerfile del backend y probar build limpio.
- Verificar que Prisma migra y genera cliente sin depender del entorno manual.

**Fase 2. Definir persistencia real**
- Crear volumen persistente para PostgreSQL.
- Crear volumen persistente para `backend/uploads`.
- Definir carpeta de backups automáticos en la PC Academia.
- Establecer política de copia:
  - backup diario de base de datos
  - backup diario de `uploads`
- Probar restauración, no solo creación de backup.

**Fase 3. Cerrar seguridad mínima de beta**
- Cambiar credenciales débiles del compose actual.
- No exponer PostgreSQL a toda la red si no hace falta.
- Mantener accesible solo el frontend/reverse proxy.
- Guardar secretos en `.env` de producción, no hardcodeados.
- Restringir Cloudflare Tunnel a dominio y rutas necesarias.
- Definir usuarios administradores iniciales y rotación básica de contraseñas.

**Fase 4. Cliente local**
- Compilar el frontend con `npm run build`.
- Servir el build desde:
  - Nginx, o
  - Express estático, o
  - IIS si quieren algo muy Windows-friendly
- En la PC administrativa usar:
  - acceso directo de Chrome/Edge en modo app, o
  - instalación como app web
- No depender de `npm start` para el uso diario administrativo.

**Fase 5. Backend + DB en PC Academia**
- Montar Docker o Docker Desktop si esa será la plataforma operativa.
- Separar `compose.dev` y `compose.prod`.
- En producción incluir:
  - `db`
  - `backend`
  - opcionalmente `frontend` o `nginx`
- Configurar reinicio automático.
- Verificar arranque tras reinicio de Windows.

**Fase 6. Punto de entrada único**
- Instalar un reverse proxy local.
- Configurar rutas:
  - `/` -> frontend compilado
  - `/api` -> backend:4000
  - `/uploads` -> backend o carpeta servida
- Confirmar que localmente todo funcione sin usar puerto `3000`.

**Fase 7. Acceso remoto**
- Instalar `cloudflared` en la PC Academia.
- Crear túnel al reverse proxy local, no al dev server.
- Publicar dominio tipo `gestion.academia.com`.
- Probar acceso externo con:
  - login
  - carga de materiales
  - descarga de materiales
  - reportes
- Definir regla operativa:
  - si la PC Academia está apagada, el acceso remoto no existirá

**Fase 8. Operación beta**
- Definir quién reinicia servicios.
- Definir cómo revisar logs.
- Definir cómo hacer respaldo.
- Definir qué hacer si:
  - falla la luz
  - falla internet
  - se llena disco por `uploads`
  - se corrompe una migración
- Hacer prueba de 1 semana en local antes de abrir remoto a usuarios reales.
